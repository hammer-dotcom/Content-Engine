# Outline: Marketing Operations Best Practices

## Working title

Marketing Operations Best Practices: Build the System Before You Add More Tools

## Angle

The best marketing operations practice is to make the path from demand activity to pipeline explicit, owned, measurable, and reviewable. Use a six-step build order for lean B2B teams.

## Hook

Most marketing operations problems look like tool problems. They are usually definition problems: two teams use the same lifecycle label, source field, or handoff term to mean different things.

## H2: Start with a shared revenue and lifecycle model

- Key point: A CRM cannot produce reliable reporting until the team agrees what each lifecycle stage means and who owns movement between stages.
- Include: a simple stage contract with definition, entry trigger, exit condition, owner, and required fields.
- Buyer stage: problem-aware to solution-aware.
- Internal link: none available.

## H2: Govern the data that every workflow depends on

- Key point: Data governance is a small set of enforced rules, not a giant documentation project.
- H3: Define the minimum record and campaign fields.
- H3: Assign ownership for quality and exceptions.
- Include: examples of required fields, accepted values, duplicate handling, and a monthly quality check.
- Buyer stage: solution-aware.
- Internal link: none available.

## H2: Design handoffs as service agreements

- Key point: A lead handoff is reliable only when the trigger, receiving owner, response expectation, and rejection path are explicit.
- Include: handoff table with trigger, owner, SLA, notification, and exception route. Avoid an unsupported numeric SLA recommendation.
- Buyer stage: solution-aware to decision.
- Internal link: none available.

## H2: Measure the operating system, not just campaign activity

- Key point: Report on the chain from source to pipeline, and pair every outcome metric with a data-quality check.
- H3: Separate activity, conversion, revenue, and system-health metrics.
- H3: Build a measurement contract.
- Include: metric table covering lead quality, stage conversion, pipeline contribution, time to follow-up, source completeness, and duplicate rate. Do not invent targets.
- Cite Google Analytics documentation for event-based measurement and journey context: https://support.google.com/analytics/answer/10089681
- Buyer stage: decision.
- Internal link: none available.

## H2: Automate stable, repeatable work

- Key point: Automation should remove predictable manual work while preserving an observable exception path.
- Include: automation checklist for routing, enrichment, notifications, campaign taxonomy checks, and reporting refreshes.
- Buyer stage: decision.
- Internal link: none available.

## H2: Add AI only where controls are clear

- Key point: AI agents are useful for bounded research, monitoring, and summarization, but they do not replace ownership, permissions, source boundaries, or review.
- Include: preflight questions about allowed actions, sources, logging, human approval, and rollback.
- Cite Google Search Central for original analysis, first-hand expertise, and transparency around automation: https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- Buyer stage: decision.
- Internal link: none available.

## H2: Use a weekly operating review and quarterly redesign

- Key point: A fixed review cadence turns operations from reactive ticket handling into managed infrastructure.
- Include: weekly review agenda and quarterly questions: what broke, what changed, what is still manual, and which definition is disputed.
- Buyer stage: decision.
- Internal link: none available.

- Key point: Fix the next constraint in the system before buying another platform.
- Include: table with stage, visible symptoms, next investment, and evidence of readiness to advance.
